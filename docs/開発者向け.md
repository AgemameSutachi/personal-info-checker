# 開発者向けの説明

ソースから動かす・配布版を組み立てる・試験する・中の作りを知りたい人向けです。使い方は [README](../README.md) を見てください。

## ソースから動かす

64bit の Python 3.11 以降（Windows）で動きます。

```
python -m pip install -r requirements.txt

python -m pii_checker app       # アプリ版（窓）。引数なしでも同じ
python -m pii_checker serve     # Web 版（合言葉入りの URL を表示してブラウザを開く）
python -m pii_checker scan \\nas01\総務 -o 結果.xlsx --csv   # コマンド版
```

コマンドの引数・終了コードは README の「コマンドで使う」と同じです（`pii-checker.exe` を `python -m pii_checker` に読み替える）。

rar・lzh・AES 暗号の zip・ディスクイメージ（ISO・VHDX 等）は 7-Zip で開きます。7z.exe は `scan --sevenzip` の指定 → 実行ファイルの隣 → Program Files → PATH の順に探し、無ければそれらの形式は理由つきで「検査不能」になります。

## 配布版（exe）を組み立てる

`python build.py` で `dist/PiiChecker/` に作ります（約 190MB）。

組み立てる PC に要るもの:

- requirements.txt の依存と PyInstaller（`python -m pip install pyinstaller`）
- 7-Zip（`C:\Program Files\7-Zip` に入れるか、`7z.exe`・`7z.dll`・`License.txt`・`readme.txt` を `vendor/7zip/` に置く。`vendor/` はリポジトリに含まないので自分で作る）。見つからないと同梱せずに組み立てを続ける（配布先に 7-Zip が要る）
- 32bit の Python 埋め込み版は python.org から自動で取得する。取れない環境では `--python32-zip <python-3.12.x-embed-win32.zip>`で渡すか、`--skip-python32` で省く（省くと Access 97 や 32bit のドライバしか無い PC で Access を読めない）
- 補助を exe にした版（access32_helper.exe）が欲しいときは、32bit の venv に pyinstaller を入れて`powershell -ExecutionPolicy Bypass -File build_helper32.ps1 -Python <32bit の python.exe>`（dist_helper32/ に作る）

できあがるもの:

- `PiiChecker.exe` … デスクトップアプリ。WebView2 が無い・窓を作れない PC では同じ画面を既定のブラウザで開く。引数を付けるとコマンドとしても動く
- `pii-checker.exe` … コンソールで使う版（`serve` で Web 版、`scan` などでコマンド版）
- `7z/` … 7-Zip（VHDX・zstd 等もこれで開く）
- `python32/` … 32bit の Python 埋め込み版と Access 補助
- `LICENSE.txt`・`THIRD-PARTY-LICENSES.txt` … このツールと、同梱する依存のライセンス文（配るときはフォルダごと渡す）

AGPL-3.0 の全文は PyMuPDF の配布物に含まれないので、`licenses/AGPL-3.0.txt` の写しから THIRD-PARTY-LICENSES.txt に入れます。

## 試験

```
python -m pip install -r requirements.txt -r requirements-dev.txt
python -m pytest tests -q
```

- 環境によって飛ばす試験がある: `test_git.py` は git が無いと、`test_ocr.py` は日本語の OCR が無いと飛ばす
- `tests/test_folderacl.py` は tmp_path の下に作ったフォルダだけ、`icacls` で Everyone の読み取りを付けて外す（ほかの場所の権限は変えない）
- `tests/test_remote.py`・`tests/test_web_connection.py` は、手元に pyftpdlib の FTP サーバーを立てて接続方式を試す
- 検体（架空の個人情報を仕込んだファイル）は試験がその場で一時フォルダに作る。Office は要らない。7-Zip を使う試験が1件あり、`vendor/7zip/7z.exe` が無ければ飛ばす
- `tests/test_access32_helper.py` は 32bit の Python で動かす試験で、64bit では飛ばす（`<32bit の python.exe> -m pytest tests/test_access32_helper.py`。32bit の Python にも pytest を入れておく）。.accdb を作る段は、64bit の Python（環境変数 `PIICHK_PYTHON64`。既定は `~/temp/venv/personal-info-checker/Scripts/python.exe`）に pywin32 があり、Access のドライバ（ACE の DAO）があるときだけ動く
- 開発中（exe でない）の Access 補助は、32bit の Python を環境変数 `PIICHK_PYTHON32` →`~/temp/venv/personal-info-checker-32` → `%LOCALAPPDATA%\Programs\Python\Python3*-32` の順に探す
- 大量の検体での回帰試験は `tests/make_corpus.py <出力先>`（Office の COM・7-Zip 等で検体を作る。pywin32 が要る）→ `tests/corpus_check.py`
- `tests/smb_check.py`・`tests/linux_check.py` は、本物の SMB サーバー・Samba/vsftpd を相手にする手動の試験（使い方は各ファイルの先頭）

- GitHub Actions（`.github/workflows/test.yml`）が、push と pull request のたびに windows-latest で black の確認と pytest を回す。black の設定（行幅 120）は pyproject.toml

## リリースの手順

1. `pii_checker/__init__.py` の `__version__` と CHANGELOG.md を更新してコミットする
2. `python build.py` で配布版を作り、`dist/PiiChecker` フォルダごと `PiiChecker-<版>.zip` に固める
3. `Get-FileHash PiiChecker-<版>.zip`（SHA256）を取る
4. `gh release create v<版> PiiChecker-<版>.zip --title "v<版>" --notes "<CHANGELOG の該当の節と SHA256>"` で Releases に置く

## 対応形式の詳細

- **Excel**: xlsx/xlsm（全シート・非表示/ごく非表示シート・コメント・図形・グラフ・ピボットキャッシュ・外部リンクの控え・文書プロパティ）、xlsb、xls（BIFF8・Excel 5.0/95・2.x〜4.0）、ods。列見出しから列の意味を推定（「氏名」列は辞書に無い名前も拾う）
- **Word**: docx（本文・表・ヘッダー/フッター・テキストボックス・コメント・脚注・変更履歴の削除文字列）、doc（97-2003・6.0/95）、rtf、odt
- **PowerPoint**: pptx（ノート含む）、ppt
- **PDF**: 本文・注釈・フォーム欄（欄名を見出しとして）・しおり・文書情報・添付ファイル。文字の無いページ（スキャン）は OCR
- **画像**: png/jpg/gif/bmp/tif（複数ページ）/webp を Windows 標準の OCR（日本語）で読む。HEIC は検査不能（要目視）
- **Access**: accdb/mdb/mde/accde（Access 97〜）。64bit ACE ODBC → 32bit 補助（Jet4 ドライバ。Access 97 も読める）→ 純 Python の順。OLE オブジェクト型の中のファイルも取り出す。ファイル全体の生データ走査で**削除済みレコードの残留**も拾う。元ファイルは一時フォルダへ複製してから開く（NAS 上にロックファイルを作らない）
- **DB**: SQLite（空き領域の残留も）、dBase、PostgreSQL ダンプ（plain/custom/directory/tar。custom は pg_restore が無くても自前で展開）、mysqldump 等の SQL 文（COPY・INSERT を列名つきで）、Oracle の exp/expdp ダンプ（簡易検査）、SQL Server の bak/mdf・InnoDB 等（簡易検査）
- **メール**: eml/mht（ISO-2022-JP 等）、msg（添付も再帰）、PST/OST（簡易検査）
- **アーカイブ**: zip（日本語名 cp932・ZipCrypto/AES）、7z（一覧の暗号化含む）、rar、lzh、cab、arj、tar/tgz/tar.gz/tar.bz2/tar.xz/tar.zst/tar.lz4、gz/bz2/xz/zst/lz4/.Z/lzip 単体、cpio、rpm、deb。入れ子も再帰
- **ディスク・OS イメージ**: ISO、WIM/ESD、VHD/VHDX、VMDK、VDI、QCOW2、DMG、生ディスク（MBR/GPT）、NTFS/FAT/exFAT/ext/squashfs のパーティション。7-Zip で中のファイルを取り出し、一定量ずつ展開→検査→片付け（一時領域を食い潰さない）。BitLocker は検査不能
- **テキスト**: 文字コード自動判定（UTF-8/16・Shift_JIS・EUC-JP・ISO-2022-JP）、CSV/TSV は表として
- **git リポジトリ**（作業フォルダの .git も bare リポジトリも）: 履歴の全オブジェクト（緩いオブジェクト・pack の差分を戻したもの）を検査し、消したファイル・過去の版に残った個人情報も拾う。blob には元のパス名を付けて表示。コミットの作者・メッセージ、索引（index）のパス名も検査
- **その他**: 拡張子に関係なく中身で判定（改名・拡張子なしも）。NTFS の代替データストリーム（隠しストリーム）。構造の分からない形式は文字列走査（簡易検査）、圧縮・暗号化された未知の形式は検査不能

## 設計の考え方

### 言い切れるかどうか

- すべての検査対象（実ファイル・アーカイブの中身・埋め込み・添付・隠しストリーム・DB の表）に、検査済み／簡易検査／要パスワード／検査不能／対象外のどれかを必ず付け、黙って飛ばすものを作らない。開けなかったフォルダと、辿らなかったリンクも記録する
- 構造を解釈できない形式は「検査済み」と呼ばず「簡易検査」と分ける
- 「列挙したファイル数」と「結果のあるファイル数」の一致をレポートに出す（取りこぼしが無い証跡）
- 形式は拡張子ではなく中身で判定する（改名・拡張子なしでも見逃さない）。中身を読まずに「対象外」「検査済み」にする判定は、目印を版のバイトまで照らし、テキストとして読めるものはテキストを先にする（「MZ-100,型番」のような CSV を実行ファイルと誤らない）
- NAS への接続が切れて読めなかったものは「検査不能」で確定させず未検査で残し、続けて切れたら検査を中断する（つながってから再開すれば取り戻せる）。使用中（排他・範囲ロック）も「権限が無い」と出さない。Windows ではどれも PermissionError / FileNotFoundError になるので、元のエラー番号で見分ける
- フォルダの識別子（ボリューム＋ファイル番号）で、同じフォルダへ戻る道（Samba がシンボリックリンクを普通のフォルダとして見せる等）を見分け、リンクとして記録する

### 検出

- 生データ走査（削除済みレコードの残留）の検出は確度を1段下げる（値の区切りが失われて取り違えうるため）
- base64 の埋め込みは、ファイルの目印があるか UTF-8 の文字として読めるときだけ取り出す（cp932 で読むと乱数でも仮名に見えるため）
- 左隣のセルを見出しとみなすとき、値まで入ったセルは「弱い見出し」として確度を下げる（見出しから外すと見落とす）
- 住所・固定電話は、同じファイルに人の手がかり（確度 中以上の氏名・生年月日・重要な種類・携帯・語つきの電話、または「名簿」「履歴書」などの題）があるときだけ 中、無ければ 低（要確認）。公共施設の所在地や番地の一覧を「可能性あり」にしないため。拾わない（消す）ことはしない
- FAX の語は会社の番号の手がかりにしない（個人の連絡先にも並ぶため）
- 自分で足す規則（利用者の規則）の正規表現は、Python の re が途中で止められないため、受け付ける前に断る: 200 文字まで・後方参照と入れ子の繰り返しを断る・長さ0に当たるものを断る・同じ文字に当たる長い繰り返しの連続（`.*.*x`・`[a-z]{1,200}[a-z]{1,200}!`。上限が 16 を超える `{m,n}` は上限なしと同じに扱う）を断る・繰り返しの中で当て方が何通りにもなる選択肢（長さの違う選択肢・1文字目が重なる選択肢。`(a|a)` は構文解析で `a(?:|)` にくくられるので、長さ0の選択肢が2つ以上あるものも数える）を断る・繰り返しの文字列に実際に当てて遅いものを断る。速さは、1024 文字の試し文字列1本の時間を、この PC で測った基準の正規表現（`\w+@`）の4倍まで受け付ける（PC の速さに左右されない。この PC では約 10ms）。試し文字列1本が 50ms を超えたら長さに関わらずすぐ断るので、受け付けで待たせない。検査では1回に 1024 文字ずつ当てる。それでも通り抜けた遅い書き方は、1ファイルの時間制限で「検査不能（時間切れ）」になる（黙って飛ばさない）
- 自分で足す規則は re.MULTILINE で当てる（速さを確かめる段も同じ）。正規表現の全体を NFKC で寄せず、全角の英数字だけを半角にし、全角の記号はその文字（本文と同じく NFKC で寄せた文字）を逃がして当てる（全体を寄せると「（本社）」がグループに、「＊」が繰り返しに化ける）
- 拾わない値（許可リスト）は正規化（全角→半角・空白・ハイフン・括弧を除く・氏名は敬称を外す）して完全一致だけを外す。外した件数は必ず判定とレポートに出す
- 異なる値はワーカーのメモリで数え、数だけを items.distinct_counts・files.distinct_counts に保存する（値もハッシュも残さない）。
  報告の目安の印は保存した件数から決め直せるので、reportflags・folderacl・jobdiff は検査器の版（signature の除外）に含めない
- アクセス権は READ_CONTROL と BACKUP_SEMANTICS だけでフォルダを開いて読む（一覧も中身も読まないので日時を変えない）。同じフォルダは1回だけ読む。
  Samba は Unix の権限を NT の ACL に写して見せるので、本物の NAS での見え方は確かめていない（目安として扱う）。
  中のファイルに届く項目（OBJECT_INHERIT を含むもの・継承の指定の無いフォルダ自身の項目）だけを数え、サブフォルダにだけ継承される項目（CONTAINER_INHERIT だけ）は数えない。
  見つからなければ「広い許可なし（目安）」と出し、「限られた人だけ」とは言い切らない（全社員グループ・Samba の Unix のグループ・ファイル個別の ACL は見ていない）
- 所有者の名前は、よく知られた SID（S-1-1-0・S-1-5-18・S-1-5-32-… など）と、この PC のアカウントの SID（NetUserModalsGet で得たこの PC の SID で始まるもの）だけ LookupAccountSidW で引き、ほかは SID の文字列のまま出す（ドメインの SID を引くとドメインコントローラーへ問い合わせが飛び、「検査先を読むほかはどこにも接続しない」を破るため）
- 前回との違いは、FTP 以外は os.path.normcase で寄せたパスで突き合わせる。前回と今回で結果に効く設定（signature と同じく、場所・道具・使い回しの指定などを除いたもの）か検査器の版（files.engine_sig）が違えば、違いの要約に添え書きを付ける。今回の検査の folder_errors（開けなかったフォルダ・辿らなかったリンク）の下にあった「無くなった」ファイルは「今回は調べられなかった」にする
- 報告の目安のジョブ全体の合計は、異なるマイナンバーは files.distinct_counts を足したもの（ファイルをまたいだ重なりは値を残していないので除けない＝上限の目安）、人数の目安は files.people_n を足したもの（ファイルごとに選ぶ種類が違いうるので、多くも少なくも出る＝上限とは言わない）。人数の目安の種類は reportflags.PEOPLE_TYPES の順を優先にして、数が同じなら先の種類を選ぶ
- 利用者の規則は、種類の件数（items.counts・conf_counts）は custom のまま、規則の名前ごとの件数を items.rule_counts に、異なる値を「custom/規則の名前:確度」の鍵で distinct_counts に持つ（画面の内訳・異なる値を規則ごとに出すため）。照合の前に CR LF・CR を LF に寄せ、位置は元の本文に戻す
- zip として開けない Office（xlsx・docx 等）・zip は、7-Zip の生の出力を理由に出さず、利用者向けの文を理由に、一時フォルダのパスを除いた短い技術情報を補足に置く（formats/archive.broken_archive）

### 読み取り

- 元のファイルは読むだけ。Access・SQLite は一時フォルダへ複製してから開く（NAS 上にロックファイルを作らない）
- Access は 64bit ACE ODBC → 32bit 補助（Jet4）→ 純 Python の順に試す。32bit 補助は標準ライブラリだけで動かし、配布版ではPython 公式の 32bit 埋め込み版を同梱する（pip 不要）
- Access の ODBC 接続文字列では、値を波括弧で囲むとパスワードが一致しない（ACE の癖）。`;{}` を含むときだけ囲む
- ツール本体は Office の COM を使わない（サービス等のセッション0から動かすと Office の COM は失敗する。Office の無い PC でも動く）
- DB へ直接つないで検査する機能は持たない。DB はダンプ・ファイルとして検査する（フォルダの下のファイルを調べる道具に絞る）
- ディスクイメージは一定量ずつ展開→検査→片付けを繰り返す（一時領域を食い潰さない）
- git の pack は過去の全版を戻して調べるので、時間制限を通常の4倍にしてある
- HTML に data URI で埋め込んだ画像も画像として検査するので、OCR を無効にすると検査不能の項目になる

### 接続方式

- SMB は自前の SMB 実装を持たず Windows の接続に任せる（共有をすべて許す開き方・日時を保つ・使用中や回線断の見分けを、フォルダ指定と同じ部品で使えるため）。SMB の接続方式ではポートを変えられない（Windows の SMB クライアントの仕様）
- FTP は標準ライブラリの ftplib。FTPS はデータ接続でも TLS のセッションを使い回す（vsftpd 等は使い回しを求める）
- FTP の一覧は MLSD → `LIST -a` → `LIST` の順に試し、隠しファイルが見えているか確かめられないサーバーではそのフォルダを要対応にする。分割アーカイブの続き・隠しストリーム・pg_dump の隣の toc.dat は取りに行かない
- 接続に失敗した理由はすべて日本語にする（パスワード違い・共有名違い・別ユーザーで接続済み（1219）・証明書・方式の違い等）
- 接続のパスワードは保存しない。覚えたパスワードを捨てるのは、パスワードを断られたとき（FTP 530・SMB 86/1326/1330）だけで、回線断では残す。サーバーは失敗の応答に印（`X-Pii-Needs-Password`・`X-Pii-Network`）を付け、画面は印で案内を出し分ける

### 画面

- GUI は tkinter を使わず、Web 版と同じ HTML/CSS/JS を pywebview で表示する
- Web 版は既定で 127.0.0.1 だけで待ち受け、起動ごとのランダムな合言葉・Host ヘッダーの検査・書き込みの要求には独自ヘッダー（`X-Requested-With`）を求める（ほかのサイトからの要求で操作されないため）。ほかの PC から使うときは `--host` と `--token` が必須
- pywebview の js_api に渡すオブジェクトは、画面から呼ぶメソッド以外の属性をすべて `_` で始める（pywebview は `_` で始まらない属性を再帰的にたどるので、窓などを持たせると exe で固まる。tests/test_desktop.py で公開名を固定している）
- WebView2 ランタイムは同梱しない（Windows 11 は標準で入っている。無ければ同じ画面を既定のブラウザで開く）

### 実測で分かった限界

- Samba は最終アクセス日時を保つ指示（SetFileTime -1）を守らず、読むとサーバー側の日時が更新される。Windows のクライアントがファイル情報を約 10 秒手元に持つので、読んだ時点では見抜けない。ツールの記録（atime_kept）は「保つ指示を出した」までを意味する
- Samba は変更日時として更新日時を返す（Linux の ctime は SMB から見えない）ので、大きさと更新日時を保ったままの書き換えは見抜けない
- FTP にはフォルダの識別子が無いので、リンクを辿って見せるサーバーのループは 64 段の深さで止めてリンクとして記録する
- git の SHA-256 リポジトリで、pack の差分の元をハッシュで引くもの（REF_DELTA）は戻せないことがある（その pack は検査不能）
- BOM の無い UTF-16 で罫線・絵文字が多いテキストは「簡易検査」になる（バイナリをテキストと誤らない側に倒している）
